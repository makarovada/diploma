# Слои данных: raw, normalized, semantic

## Назначение слоев

- `raw` - неизмененные данные из источников + технические ingest-метаданные.
- `normalized` - структурно нормализованные таблицы (типы, даты, телефон/email/ИНН, базовая очистка).
- `semantic` - прикладные витрины для аналитики, построенные dbt-моделями.

## Принципы

1. Коннектор не должен писать напрямую в бизнес-витрину.
2. Нормализация не должна кодировать бизнес-логику конкретного отчета.
3. Бизнес-агрегации и доменные метрики живут в dbt-моделях.

## Пример цепочки

Для Яндекс Метрики:

- `raw.yandex_metrika__visits`
- `normalized.yandex_metrika__visits`
- `semantic.marketing_yandex_metrika_visits` (имя зависит от materialization/alias dbt)

## Операционные требования

- Каждая таблица в `raw` должна иметь ingest-метаданные и трассировку до source stream.
- `normalized` должен быть детерминированным относительно входа из `raw`.
- `semantic` должен пересобираться через `dbt run` без ручного SQL в приложении.
