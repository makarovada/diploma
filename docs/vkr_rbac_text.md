# Текст для ВКР: роли, доступ и UI-контур

Материал для раздела ВКР о разграничении доступа и пользовательском контуре платформы DataNorma.

## 1. Модель доступа (workspace ACL)

Единица изоляции — **рабочее пространство** (`workspace`). Пользователь видит только пространства из `user_workspace`.

- **Администратор пространства** (`user_workspace.is_admin`) — полный доступ, приглашение участников, выдача прав.
- **Участник** — набор строк в `workspace_member_permission` (например `source.create`, `connection.sync.run`).
- **Делегирование на объект** — таблица `resource_grant` (уровни `view` / `edit` / `manage`); выдаёт создатель ресурса или администратор.

Каталог прав: `GET /api/v1/permissions/catalog`. Исторические глобальные роли (`role`, `user_role`) в проверках API не участвуют.

## 2. Аутентификация и авторизация

- Веб-приложение: `python -m datanorma.web`.
- JWT (Bearer); активное пространство — `X-Workspace-Id` и `allowed_workspace_ids` в claims.
- `GET /api/auth/me` → `permissions`, `is_workspace_admin`.
- При отсутствии прав — `403 Forbidden`.

Устаревшая матрица: `GET /api/rbac/matrix`.

## 3. Dagster и пользовательский интерфейс

В архитектуре проекта разделены два контура:

- **Операционный контур** - Dagster (материализация assets, расписания, проверки, диагностика).
- **Пользовательский контур** - web UI на FastAPI + React SPA (`/ui/`), ориентированный на бизнес-сценарии.

Такое разделение позволяет:
- оставить оркестрацию в специализированном инструменте;
- предоставить отдельный пользовательский интерфейс для ролей бизнеса и интеграции;
- явно валидировать доступы по ролям в web/API.

## 4. Аргументация для приемки

Для подтверждения корректности RBAC в ВКР рекомендуется показать:

- таблицу "роль x операция" на основе `/api/rbac/matrix`;
- скриншоты одних и тех же разделов под разными ролями;
- примеры успешных (`2xx`) и запрещенных (`403`) обращений;
- соответствие пунктов меню и фактических API-доступов.

Демо-учетки для иллюстраций:
- `seed_admin / AdminDemo2026`
- `seed_integrator / IntegratorDemo2026`
- `seed_analyst / AnalystDemo2026`

## 5. Ограничения и корректные формулировки

Для академически корректного описания MVP:

- указывать, что часть API-маршрутов оркестрации реализована в облегченной форме;
- отделять "управление доступом" (реализовано) от "enterprise IAM" (вне текущего объема);
- фиксировать, что мультитенантность присутствует базовым контуром и может быть расширена.
