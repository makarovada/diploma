# Фрагмент для ВКР: роли, доступ, Dagster vs собственный UI

## Роли и смысл

В прототипе **DataNorma** закреплены три роли (см. таблицы `role`, `app_user`, `user_role` в PostgreSQL):

1. **Администратор платформы** (`platform_admin`) — управление пользователями и ролями (просмотр), конфигурации интеграций, доступ к операционной консоли оркестрации, полный доступ к данным мониторинга и витрине.
2. **Интегратор данных** (`data_integrator`) — настройка и сопровождение цепочки данных: просмотр сырого слоя в staging, состояния синхронизации, профилей маппинга, журналов пайплайна, витрины; доступ к операционной консоли (Dagster) для запуска и диагностики; **без** администрирования учётных записей и секретов на уровне UI-админки.
3. **Аналитик** (`analyst`) — **только чтение** продуктовых данных: витрина, справочники, матрица доступа (как документация), без staging, без админских экранов и без изменения конфигураций.

## Аутентификация и авторизация

Веб-приложение (порт по умолчанию **8080**, `python -m datanorma.web`) выдаёт **JWT** после проверки логина и **SHA-256** хеша пароля из БД. В claims токена передаётся список имён ролей; **каждый защищённый маршрут REST** сопоставлен с **операцией** из матрицы RBAC (`datanorma/web/rbac_matrix.py`): при отсутствии пересечения ролей пользователя с допустимыми для операции возвращается **403**.

Пароли в демо-сидере задаются явно (см. `scripts/seed_database.py` и подсказку на экране входа); для реальной эксплуатации в тексте диплома указать необходимость замены на политику паролей и, при необходимости, **bcrypt/argon2**.

## Dagster и «20 экранов»

**Dagster** в работе позиционируется как **операционная консоль** (технический инструмент) для администратора платформы и интегратора данных: материализация assets, логи, расписания. Для соответствия методичке **основной пользовательский контур** — **веб-клиент на FastAPI + Jinja2** (фаза C): отдельные URL `/app/...` под формы и таблицы (см. `docs/phase_c_routes.md`). Дополнительно сохранён одностраничный интерфейс **`/ui/`** (JWT в `localStorage`).

## Критерий приёмки (для главы / приложения)

- Таблица **«роль × операция»** формируется из кода (`GET /api/rbac/matrix`) и отображается в UI (экран 2).
- **Скриншоты** под учётками `seed_admin`, `seed_integrator`, `seed_analyst` иллюстрируют различие доступных пунктов меню и ответов API (в т.ч. **403** при попытке открыть чужой раздел).
